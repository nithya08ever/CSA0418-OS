8.1 Introduction
The CPU operates in two modes: user mode and kernel mode. These modes protect the operating system from unauthorized operations performed by application programs.

In the Smart Hospital, CPU protection is important because patient-monitoring applications must operate reliably without interference from other programs.

8.3 Privileged Instructions and Mode Bit
A privileged instruction is an instruction that can only be executed in kernel mode.

Examples include:
- Disabling or enabling interrupts.
- Modifying memory-management registers.
- Controlling certain hardware devices.
A hardware mode bit indicates the current CPU execution mode.
- User mode: restricted execution.
- Kernel mode: privileged execution.
If a user application attempts to execute a privileged instruction, the CPU generates an exception and transfers control to the operating system.
8.4 Interrupts, Traps and Timer
Interrupt: An event generated by hardware that requires CPU attention.

Trap: A software-generated exception or intentional transfer of control, such as a system call.

Timer interrupt: A hardware timer generates an interrupt after a configured interval. It allows the operating system to regain CPU control and schedule another process.
Hospital application
When a bedside monitor detects an important patient event, an interrupt can notify the CPU to process the event.

A timer interrupt also helps the operating system prevent one process from occupying the CPU indefinitely.
8.5 Why Cannot a User Program Disable Interrupts?
A user-level application must not be allowed to disable hardware interrupts because doing so could prevent the operating system from responding to important events.

For example, a patient-monitoring application could prevent other processes from receiving CPU time if it could disable interrupts.

Therefore:
1. Disabling interrupts is a privileged operation.
2. User programs execute in restricted mode.
3. The CPU prevents unauthorized privileged instructions.
4. The operating system controls interrupt handling.
Evaluation: This protection prevents ordinary applications from interfering with critical operating-system operations.
8.6 Memory Protection and Isolation
Memory protection prevents one process from accessing another process's protected memory.

The operating system uses memory-management hardware, such as the Memory Management Unit (MMU), to enforce memory access permissions.

Hospital example: A nurse's tablet application should not be able to directly access the memory of another application containing confidential patient information.

Memory isolation helps prevent accidental or unauthorized access between processes.
8.7 Alternative Analysis: Polling vs Interrupts
Alternative question: What if bedside patient monitors use polling instead of interrupts?
A. Polling
Polling is a technique where the CPU repeatedly checks whether a device requires attention.

Advantages:
- Simple implementation.
- Predictable checking intervals.
- Useful for certain simple embedded systems.
Disadvantages:
- Wastes CPU cycles when no event occurs.
- Detection may be delayed until the next polling cycle.
- Can increase power consumption.
B. Interrupt-driven I/O
Interrupt-driven I/O allows a device to notify the CPU when an event requires attention.

Advantages:
- CPU does not need to continuously check devices.
- Faster response to asynchronous events.
- Better CPU utilization.
Disadvantages:
- Interrupt handling introduces overhead.
- Excessive interrupts can affect performance.
- Requires proper interrupt prioritization.
Comparison

Recommendation: Interrupt-driven I/O is recommended for bedside patient monitors because it avoids continuous polling and can provide faster event notification. The complete system must still be tested to guarantee the 10 ms alarm deadline.
8.8 Conclusion
CPU protection mechanisms separate user-mode and kernel-mode execution to prevent unauthorized access to hardware and system resources. Privileged instructions, interrupts, traps, timer mechanisms and memory protection help maintain operating-system stability.

For the Smart Hospital, interrupt-driven I/O is preferable for bedside monitoring because it provides efficient event handling and supports timely alarm processing.
