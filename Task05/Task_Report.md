# Task 5 – System Calls and Their Role in Operating Systems

## 1. Objective
To understand system calls, their categories, parameter-passing methods and execution using Linux `strace`.

## 2. Categories of System Calls
1. Process control – `fork()`, `exec()`, `wait()`
2. File management – `open()`, `read()`, `write()`, `close()`
3. Device management – `ioctl()`
4. Information maintenance – `getpid()`, `time()`
5. Communication – `pipe()`, `socket()`
6. Protection – `chmod()`, `chown()`

## 3. Working of read()
The application calls `read()`. The C library prepares the request, and the CPU transfers execution into kernel mode through a system-call instruction. The kernel validates the arguments, performs the read operation and returns the result to the application in user mode.

## 4. Parameter-Passing Methods
- Registers: Parameters are stored in CPU registers.
- Memory block: Parameters are stored in memory and their address is passed.
- Stack: Parameters are passed through the program stack.

## 5. Practical Demonstration
A C program was developed using `open()`, `read()` and `close()` to read a sample text file.

**Compilation:**
`gcc -Wall -Wextra system_call_demo.c -o system_call_demo`

**Execution:**
`./system_call_demo`

**Tracing:**
`strace -e trace=openat,read,close ./system_call_demo`

## 6. Observations

| System call | Observed result | Meaning |
|---|---|---|
| openat() | 3 | File opened successfully |
| read() | 43 bytes | File content read successfully |
| close() | 0 | File descriptor closed successfully |

The program displayed: `Smart Hospital Operating System Assignment`.

The `strace` output confirmed the file operations performed by the application. Additional calls involving shared libraries were generated during program startup.

## 7. C Library vs Direct System Calls

| C library functions | Direct system calls |
|---|---|
| fopen(), fread(), fwrite(), fclose() | open(), read(), write(), close() |
| Higher-level interface | Lower-level interface |
| Supports library buffering | Application controls read/write buffer sizes |
| Can reduce system-call frequency | Each explicit operation may invoke a system call |

For a file of size N and buffer size B, approximately `ceil(N/B)` read operations are required when reading until EOF. Library buffering can reduce kernel system-call frequency.

## 8. Conclusion
System calls provide controlled access to operating-system services. The practical successfully demonstrated file opening, reading and closing operations. The `strace` utility helped identify and analyse the system calls generated by the program.
